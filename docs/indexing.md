# Индексированный поиск и голосовые

## Включение и отключение

В административный `config.json` добавьте секцию (остальные поля и ACL остаются прежними):

```json
"indexing": {
  "enabled": true,
  "database": "/var/lib/telegram-acl-mcp/index.sqlite3",
  "history_since": "2026-06-23T00:00:00+03:00",
  "sync_interval_seconds": 30,
  "page_size": 100,
  "transcribe": true,
  "backend": "telegram",
  "request_interval_seconds": 2,
  "max_attempts": 8,
  "max_pending_polls": 60,
  "max_queue_size": 10000,
  "max_results": 50,
  "max_context": 10
}
```

Замените дату начала на нужную. Если `history_since` отсутствует, при первом запуске база фиксирует начало как «сейчас минус `history_days`» (по умолчанию 90). При последующих запусках это начало сохраняется: автоматического удаления сообщений старше 90 дней нет. Изменение `history_days` влияет только на новую базу. Для изменения периода существующей базы явно задайте `history_since`: прогресс загрузки будет сброшен, более ранние сохранённые сообщения удалены при сужении периода.

Для отключения достаточно:

```json
"indexing": { "enabled": false }
```

Либо удалите всю секцию. После перезапуска сервер:

- объявляет только исходные пять инструментов;
- отклоняет прямые вызовы индексированных инструментов, даже если клиент сохранил их описание;
- не открывает и не создаёт SQLite, не запускает синхронизацию и транскрибацию;
- возвращает прежний формат сообщений без полей транскрипции и метаданных индекса.

Уже существующая БД при отключении сохраняется на диске, но не используется. После повторного включения обработка продолжается. Каталог `StateDirectory` может существовать и при отключённом режиме; это не означает, что создана БД.

Все настройки читаются при запуске; переключение режима требует перезапуска службы и обновления списка MCP-инструментов/переподключения Hermes. Отдельного переключателя в Hermes нет.

`transcribe=false` при `enabled=true` оставляет индекс текста, имён файлов и ссылок, но выключает очередь транскрибации, скрывает инструмент расшифровки и исключает ранее сохранённые транскрипции из выдачи и поиска. Они сохраняются в БД для последующего включения.

## Инструменты

| Инструмент | Условие доступности | Назначение |
|---|---|---|
| Пять исходных методов | Всегда | Прямое чтение и текстовый поиск Telegram |
| `telegram_search_context` | `indexing.enabled=true` | Поиск по локальному индексу всех разрешённых или выбранных чатов |
| `telegram_get_index_status` | `indexing.enabled=true` | Период истории, прогресс и ошибки синхронизации, готовность голосовых |
| `telegram_transcribe_voice` | Также `transcribe=true` | Возврат готовой транскрипции или постановка приоритетного задания |

Пример аргументов `telegram_search_context`:

```json
{
  "query": "отчет",
  "outgoing_only": true,
  "date_from": "2026-09-01T00:00:00+03:00",
  "sources": ["text", "voice", "filename", "url"],
  "limit": 20,
  "context_before": 2,
  "context_after": 2
}
```

`chat_keys` по умолчанию содержит все чаты ACL; можно передать непустой список выбранных ключей. Никакого обнаружения других чатов нет. `sender_id` фильтрует автора, `outgoing_only` — сообщения владельца используемой Telegram-сессии. Даты относятся к отправке сообщения, а не к сроку поручения. Интервал `[date_from, date_to)`, даты обязательно с часовым поясом.

Все разделённые пробелами фрагменты запроса должны встретиться в выбранных полях одного сообщения. Поиск использует SQLite FTS5 trigram, Unicode NFKC, регистр не учитывается, `е` и `ё` эквивалентны. Поиск по подстрокам поддерживает `отчет` → `отчета`, фрагменты имени и URL. Это не полноценный морфологический или семантический поиск: `отчета` не обязательно найдёт `отчет`, а `доклад` не станет синонимом автоматически. Hermes должен использовать основы слов и несколько запросов с синонимами. FTS-операторы из пользовательского ввода не исполняются: фрагменты воспринимаются буквально. Очень широкие запросы ограничены по времени; при отказе сузьте период или запрос.

Выдача содержит `chat_key`, сообщение, `matched_sources`, фрагменты совпадений и контекст. `reply_to` содержит исходное сообщение ответа, если оно есть в индексе того же чата. Контекст не обходит другие чаты и не восстанавливает всю ветку обсуждения.

Для следующей страницы передайте `next_cursor` как `cursor`, сохранив остальные аргументы. Курсор привязан к запросу, области доступа и версии индекса. Если индекс изменился, сервер попросит начать поиск заново — это предотвращает незаметные пропуски при изменении сортировки по релевантности.

Пример вызова `telegram_transcribe_voice`:

```json
{ "chat_key": "project_a", "message_id": 123 }
```

Метод не ждёт завершения расшифровки. Если очередь заполнена, сообщение может иметь `not_queued`; фон поставит его в очередь после освобождения места. Состояния: `not_queued`, `queued`, `processing`, `pending`, `ready`, `failed`, а при отключённой транскрибации — `disabled`. После выяснения причины ошибки можно повторить с `"retry_failed": true`; обычный повторный вызов не сбрасывает лимит попыток. Сообщения вне заданного периода истории этим методом не индексируются.

Транскрипция отделена от текста/подписи и помечена как машинная, не дословная цитата. Исходное сообщение не изменяется. `telegram_transcribe_voice` помечен в MCP как инструмент с побочным действием: он может изменить локальную очередь и инициировать распознавание в Telegram; остальные методы чтения остаются read-only.

## Полнота и актуальность

В `coverage` и статусе по каждому чату доступны:

- `history_since`, `history_done`, фактически самая ранняя и поздняя даты;
- `last_sync` — время последнего опроса, догнавшего новые сообщения;
- `last_reconciled` — время завершения полного прохода сверки загруженного периода;
- количество голосовых, готовых транскрипций, недоступных транскрипций и состояния очереди;
- безопасный код ошибки синхронизации без содержания сообщений и секретов.

`incomplete_reasons` объясняет известные пробелы. Поиск без нижней даты явно предупреждает об истории до `history_since`. Даже если список причин пуст, индекс является периодически обновляемым состоянием, а не транзакционным снимком Telegram. Hermes должен учитывать время последнего обновления и не трактовать пустую выдачу как доказательство отсутствия поручения.

Сначала загружаются последние сообщения, затем старая история страницами. Новые сообщения обрабатываются по отдельному курсору, чтобы заполнение истории их не блокировало. Недавние сообщения перепроверяются в каждом цикле; после первичной загрузки старые диапазоны сверяются по кругу. Поэтому изменения и удаления старых сообщений отражаются с задержкой полного прохода. Удаление из индекса выполняется только для успешно прочитанного диапазона, не при сетевой ошибке. Получение соседнего контекста из индекса может быть неполным.

На вопрос «кому я поручил отчёт на завтра» следует искать собственные сообщения по основам слов, читать контекст и указывать `chat_key` + `message_id`. Значение «завтра» в исходном поручении определяется относительно даты сообщения и часового пояса, а не автоматически относительно сегодняшнего дня. Если работал отдельный аккаунт, `outgoing_only` относится к нему; для поиска поручений вашего личного аккаунта нужен его `sender_id` и доступ служебного аккаунта к соответствующим сообщениям.

## Транскрибация

Реализован только native backend `telegram`: `messages.TranscribeAudioRequest`. Premium нужен у аккаунта серверной Telegram-сессии. При отсутствии Premium текстовая индексация продолжает работать, задания сохраняются, статус показывает `premium_required`; наличие Premium повторно проверяется примерно раз в пять минут.

Аудио не скачивается нашим сервером и не отправляется сторонним STT-провайдерам. Индексируются также видеосообщения-кружки. Содержимое документов не читается, URL извлекаются из текста, entities, метаданных уже полученного preview и URL-кнопок без открытия страниц или нажатия кнопок.

Фоновая задача делает один запрос транскрибации за попытку. `pending` сохраняется в SQLite и опрашивается повторно; частичный текст не попадает в индекс как готовый. `FloodWait` откладывает фоновые запросы, временные ошибки повторяются с увеличением задержки. Неудачные и слишком долго ожидающие задания получают `failed`. Очередь и результаты переживают перезапуск, незавершённые задания возвращаются в очередь. Замена голосового вложения инвалидирует старую транскрипцию.

Служба использует один процесс, один Telethon-клиент, две фоновые asyncio-задачи и постоянную очередь SQLite. Ожидания фоновой работы не удерживают блокировку исходного `Reader`. Блокировка файла БД запрещает случайный параллельный запуск второго экземпляра на той же базе. SQLite-операции выполняются короткими транзакциями без сетевых ожиданий. Другая Telegram-учётная запись требует другой базы; несовпадение account ID останавливает запуск индексированного режима.

## Развёртывание и хранение

Дополнительных Python-зависимостей нет. Нужна сборка SQLite с FTS5 и tokenizer `trigram` (SQLite 3.34+). Отсутствие поддержки обнаруживается при создании базы; сервер не подменяет индексированный режим скрытым текстовым fallback. В комплектном systemd unit добавлены:

```ini
StateDirectory=telegram-acl-mcp
StateDirectoryMode=0700
```

Это разрешает службе запись в `/var/lib/telegram-acl-mcp` при `ProtectSystem=strict`. Путь по умолчанию не требует ослаблять защиту `/opt` или `/etc`. Если нужен другой путь, администратор должен отдельно обеспечить права и разрешить запись через systemd. На Windows задайте абсолютный путь и ограничьте ACL каталога средствами Windows.

После установки обновлённого пакета и unit администратор выполняет:

```bash
systemctl daemon-reload
systemctl restart telegram-acl-mcp
systemctl status telegram-acl-mcp --no-pager
```

Затем переподключите Hermes к MCP, вызовите `telegram_get_index_status` и дождитесь нужного покрытия. Сначала проверьте качество native-транскрипций на собственных записях: особенно имена, даты и окончания фраз. Автоматические тесты используют имитацию Telegram; они не подтверждают качество распознавания конкретных аудиозаписей.

База содержит незашифрованный текст переписки. Не монтируйте каталог БД в контейнер Hermes; храните его у служебного пользователя. При старте включённого режима данные чатов, отсутствующих в текущем ACL, удаляются из активных таблиц и поиска. Это логическое удаление, а не гарантированное стирание блоков диска или резервных копий. При отключённом режиме очистки БД нет, поскольку она вообще не открывается.

Для резервного копирования остановите службу, скопируйте каталог состояния целиком вместе с SQLite WAL/SHM, затем запустите службу. Для восстановления остановите службу, восстановите согласованную копию и права служебного пользователя, затем запустите её. Не копируйте только основной файл активной WAL-базы. Очередь и прогресс синхронизации входят в резервную копию. Файл `.lock` не хранит постоянную блокировку: ОС освобождает её при завершении процесса.

Для полного перестроения администратор может указать новый путь БД и перезапустить службу. Старую БД удаляют отдельно по принятой политике хранения. Конфигурация и секреты продолжают принадлежать администратору; Hermes не получает инструментов изменения ACL, настроек, файлов БД или запуска произвольного SQL.
