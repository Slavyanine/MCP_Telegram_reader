# Панель администратора

Панель дополняет существующую CLI. Логика MCP reader, индексации и транскрибации
не меняется. Рабочий конфиг загружается службой один раз: применение настроек
останавливает и запускает `telegram-acl-mcp.service`. После изменения ACL или
режимов переподключите Hermes, чтобы обновить схемы инструментов.

## Возможности

- Пошаговый вход: API ID/API Hash, телефон, код Telegram, при необходимости 2FA.
  Пустой API Hash означает использование сохранённого. Способ доставки кода
  определяет Telegram, SMS не гарантируется. Незавершённый вход истекает через
  10 минут. Код и пароль не записываются в файлы и журналы.
- Список диалогов загружается порциями по 100, включая доступные архивные диалоги
  Telethon. Поиск и фильтр работают по уже загруженным строкам. Выбор не теряется
  при загрузке следующей страницы. Конфиг может включать до 10000 чатов.
- `key` и `title` редактируются, `kind`, `peer_id`, `access_hash` берутся на
  серверной стороне. `access_hash` не передаётся в JavaScript. Уже разрешённые
  чаты сохраняются даже при неполном списке диалогов. Пустой ACL запрещён.
- Индексация, транскрибация, выбор Telegram/Yandex/Deepgram; API-ключи можно
  заменить, сохранённые значения не возвращаются браузеру. Дополнительные
  параметры индекса и провайдеров из существующего конфига сохраняются.
- Черновик сохраняется отдельно. Проверка изменений предшествует применению.
  При новом входе сессия автоматически сохраняется в защищённый черновик:
  выберите чаты перед применением. Сброс черновика возвращает рабочие настройки.

Новый вход всегда готовит новый путь SQLite, даже при повторной авторизации того
же аккаунта; старые базы не удаляются. Это исключает смешивание аккаунтов и
параметров доступа. Панель управляет одним активным аккаунтом, а не списком
сохранённых профилей. Отмена не отзывает уже созданную Telegram-авторизацию;
при необходимости завершите её в разделе Telegram «Устройства».

Выключение индексации не удаляет базу. Выключение транскрибации сохраняет готовые
результаты, но они не выдаются как активные транскрипции. Смена провайдера
сохраняет готовые результаты; текущий worker переставляет `queued`/`pending`
задания в очередь нового провайдера. `failed` автоматически не повторяются.
Текущая реализация Telegram backend требует Premium; Yandex поддерживает
короткие mono OggOpus до 30 секунд/1 МБ; Deepgram использует лимиты конфига.

## Архитектура и доступ

`telegram-acl-admin-web` работает отдельным непривилегированным пользователем,
слушает только `127.0.0.1:8766`, проверяет отдельный Bearer token, Host и Origin.
Нет cookies и CORS; токен живёт в памяти вкладки, ответы имеют `no-store`, CSP
запрещает сторонние скрипты и встраивание. Доступ рассчитан на SSH-туннель.
Публичное проксирование HTTP этой версии не предусмотрено.

`telegram-acl-admin-broker` работает от root, доступен только через Unix socket
`/run/telegram-acl-admin/broker.sock` группе `telegram-acl-admin`. Он принимает
фиксированный набор операций, не принимает shell-команды, пути файлов или имя
systemd-службы из HTTP. Только broker читает Telegram-секреты, создаёт сессии и
обновляет root-owned конфиг. Web-пользователь имеет административные полномочия
через этот socket: не добавляйте в его группу Hermes и других пользователей.
MCP-токен не даёт доступа к панели; административные операции не доступны MCP.

Черновики, журнал восстановления и резервные копии находятся в
`/var/lib/telegram-acl-admin` (root, 0700). Новые секреты создаются отдельными
неизменяемыми ревизиями в `/etc/telegram-acl-mcp/admin-revisions`,
`root:telegram-mcp`, каталоги 0750, файлы 0640. Рабочий конфиг атомарно заменяется
и указывает на согласованный комплект файлов ревизии. Старые секреты не
перезаписываются. Не удаляйте ревизии, на которые ссылаются рабочий конфиг или
резервные копии. Архивируйте вместе `/etc/telegram-acl-mcp` и состояние панели.

## Установка на существующий Linux VPS

Ниже команды для root после копирования обновлённых исходников в
`/opt/telegram-acl-mcp`. Базовый сервер и пользователь `telegram-mcp` должны уже
существовать. Конфигурация должна быть рабочей. Базы для управления через панель
должны располагаться внутри `/var/lib/telegram-acl-mcp`; нестандартный путь
снаружи этого каталога требует предварительного переноса при остановленной
службе и обновления JSON. Зависимости уже присутствуют в `requirements.lock`.

```bash
/opt/telegram-acl-mcp/.venv/bin/python -m pip install --no-deps /opt/telegram-acl-mcp
id telegram-acl-admin || useradd --system --user-group --no-create-home --shell /usr/sbin/nologin telegram-acl-admin
install -d -o root -g telegram-acl-admin -m 0750 /etc/telegram-acl-admin
```

Создание отдельного токена без вывода в журнал терминала; существующий файл
намеренно не перезаписывается:

```bash
umask 077
/opt/telegram-acl-mcp/.venv/bin/python -c 'import secrets; from pathlib import Path; p = Path("/etc/telegram-acl-admin/token.secret"); f = p.open("x"); f.write(secrets.token_urlsafe(48)); f.close()'
chown root:telegram-acl-admin /etc/telegram-acl-admin/token.secret
chmod 0640 /etc/telegram-acl-admin/token.secret
install -o root -g root -m 0644 /opt/telegram-acl-mcp/deploy/telegram-acl-admin-broker.service /etc/systemd/system/
install -o root -g root -m 0644 /opt/telegram-acl-mcp/deploy/telegram-acl-admin-web.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now telegram-acl-admin-broker telegram-acl-admin-web
systemctl status telegram-acl-admin-broker telegram-acl-admin-web --no-pager
```

На компьютере администратора:

```bash
ssh -N -L 8766:127.0.0.1:8766 ADMIN@VPS
```

Откройте `http://127.0.0.1:8766` в браузере и введите токен из
`/etc/telegram-acl-admin/token.secret`, полученный через защищённый
административный доступ. Не открывайте порт 8766 наружу. После обновления пакета
перезапускайте обе административные службы; это само по себе не меняет MCP.

## Применение и восстановление

1. Сохранение проверяет выбор и настройки; применение повторно проверяет
   авторизацию Telegram, полный конфиг существующим `load_config`, пути и права.
2. Контрольная сумма конфига и исходных секретов обнаруживает внешнее изменение.
   Если конфиг изменён, нужен сброс черновика. Версия черновика защищает от
   сохранения устаревшей вкладки. Не редактируйте файлы вручную во время применения.
3. Broker останавливает MCP и копирует старый JSON, секреты и затрагиваемые SQLite
   вместе с WAL/SHM. Копия `secrets.json` сопоставляет имена резервных файлов с
   исходными путями. Предыдущие секреты также остаются на месте: штатный откат
   возвращает ссылки на них, не перезаписывая файлы. Базы не открываются из панели.
4. Записывается журнал восстановления, устанавливается новая конфигурация,
   запускается MCP; настоящий запрос `tools/list` проверяет ACL и набор режимов.
5. При сбое восстанавливаются конфиг и снимки баз, возвращается прежнее состояние
   службы. Если broker прерван, журнал обрабатывается при его следующем запуске.
   При ошибке восстановления журнал сохраняется, чтобы не потерять возможность
   повторного восстановления. Не запускайте MCP вручную, пока идёт восстановление.

Проверка запуска подтверждает доступность MCP, авторизацию сессии при старте и
схемы инструментов. Она не обещает немедленно заполненный индекс и не проверяет
распознавание реального аудио или оплату API-провайдера. После применения проверьте
чтение выбранного чата и статус индекса через MCP.

Кнопка применения ждёт завершения; закрытие браузера не отменяет уже начатую
операцию. При потере HTTP-соединения проверьте состояние перед повтором.
Резервные копии содержат переписку и занимают место: автоматическое удаление не
реализовано. Политику хранения задаёт администратор VPS. Для удаления старых
копий дождитесь завершения операций и убедитесь, что нет `transaction.json`.

## Проверка

```bash
cd /opt/telegram-acl-mcp
.venv/bin/python -m pytest -q
```

Тесты используют имитацию Telegram/systemd и проверяют HTTP-защиту, авторизацию,
ACL, переключение аккаунта, конфликты, применение и восстановление. Для выпуска
на конкретный VPS дополнительно проверьте живой вход с 2FA, загрузку диалогов,
перезапуск через systemd и чтение чатов. Windows позволяет запускать тесты и
просматривать UI с тестовым backend; производственный broker требует Linux.
